**ESP32 capability detection: "Unknown" firmware / missing T-800 caps on first navigation** — `m1_esp32_caps_init()` used to permanently skip the `AT+CMD?` probe whenever the ESP32 AT task was not already running, instead of starting it (as `wifi_do_scan()` already does).  Capability-gated scenes (`DELEGATE_FEATURE` in `m1_wifi_scene_menu.c` and similar) only start the SPI transport before checking a capability, not the AT task, so navigating directly to a gated feature (e.g. WiFi -> 802.15.4 -> Zigbee Scan) as the first ESP32 interaction left detection stuck at "Unknown" with no capability bits set.  `wifi_pmkid_at()` had the same issue in a different form: it checked the `M1_ESP32_CAP_BEACON` T-800 gate before bringing up the ESP32 at all, so a fresh navigation to Attacks -> PMKID Grab reported "Requires T-800" even with genuine dag T-800 firmware flashed.  Fixed by starting the AT task inside `m1_esp32_caps_init()` when needed, and by reordering `wifi_pmkid_at()` to initialize the ESP32/AT task before its capability gate.
